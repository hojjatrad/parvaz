## محدودیت مهاجرت از نسخهٔ قبلی

شناسهٔ برنامه همان `com.parvaz.tunnel` باقی مانده، اما امضا عوض شده است.
بنابراین نصب مستقیم نسل جدید روی APKهای دارای امضای قدیمی ممکن نیست.
پیش از حذف نسخهٔ قدیمی، بکاپ کانفیگ‌ها/تنظیمات و رمز بکاپ را نگه دارید.
از اولین نصب با این کلید به بعد، نسخه‌های دارای همین امضا و versionCode بالاتر قابلیت ارتقا دارند.
هیچ برنامه‌ای توسط این فرایند از گوشی کاربر حذف نمی‌شود.

## پشتیبان کلید — ضروری

مالک پروژه باید بستهٔ حساس `parvaz-signing-backup-generation-3.zip` را که جداگانه برای دانلود در محیط گفتگو ارائه شده،
همین حالا دریافت کند. این بسته شامل فایل PKCS12 **و رمز آن** است؛ ZIP به‌خودی‌خود رمزگذاری‌شده نیست.
آن را در فضای امن/رمزگذاری‌شده و ترجیحاً یک پشتیبان آفلاین نگه دارید.
آن را در مخزن عمومی، GitHub Releases، issue، artifact عمومی یا متن چت بارگذاری نکنید.
باقی‌ماندن فایل در محیط گفتگو تضمین پشتیبان‌گیری دائمی نیست.

ساخت کلیدی با همان Alias یا رمز، کلید قبلی را بازسازی نمی‌کند. از دست‌دادن این کلید یعنی
از دست‌دادن امکان به‌روزرسانی هم‌امضا برای این نسل نیز؛ پس پشتیبان اصلی را حتی پس از تنظیم Secrets نگه دارید.

## چهار Repository Secret

در این صفحه:

https://github.com/hojjatrad/parvaz/settings/secrets/actions

چهار Secret زیر را بسازید یا مقدار چهار مورد موجود را با دکمهٔ ویرایش جایگزین کنید. مقدار هر کدام، محتوای فایل هم‌نام با پسوند `.txt` در بستهٔ پشتیبان است:

| نام Secret | محتوا |
|---|---|
| `PARVAZ_KEYSTORE_BASE64` | فایل PKCS12 به‌صورت Base64 |
| `PARVAZ_KEYSTORE_PASSWORD` | رمز فایل کلید |
| `PARVAZ_KEY_ALIAS` | Alias کلید |
| `PARVAZ_KEY_PASSWORD` | رمز کلید |

**نام و مقدار یکسان نیستند.** در فرم آفلاین خصوصی `setup-secrets.html`، دکمهٔ سبز «کپی مقدار برای کادر Secret» متن واقعی هر فایل را کپی می‌کند. اسم فایل یا اسم Secret نباید در کادر مقدار قرار بگیرد.

Base64 رمزگذاری امنیتی نیست؛ فایل آن نیز خصوصی است. مقادیر را در **Secrets** بگذارید، نه Variables.
`PARVAZ_KEYSTORE_PATH` نیازی به Secret ندارد؛ workflow آن را به مسیر موقت runner تنظیم می‌کند.

اگر GitHub CLI روی رایانهٔ مالک نصب و به حساب صحیح وارد شده باشد، اسکریپت `import-secrets.sh` داخل
بستهٔ خصوصی می‌تواند این چهار فایل را با stdin بارگذاری کند؛ برای استفاده از آن توکن را در چت نفرستید.

**Deploy Key اجازهٔ تنظیم Repository Secrets از طریق API را نمی‌دهد.** این مرحله باید یک‌بار توسط
مالک مخزن در رابط GitHub یا CLI حساب خودش انجام شود.

## ساخت و انتشار

- `Android compilation and unit tests`: ساخت debug و تست‌های Android بدون کلید انتشار؛ خروجی debug منتشر نمی‌شود.
- `Build and publish signed prerelease`: بررسی Secretها، تست‌ها، تطبیق کلید با اثرانگشت، ساخت release، بررسی امضای واقعی APK، شناسه/نسخه و checksum؛ سپس انتشار دو APK در Releases.
- هستهٔ Xray با نسخه و SHA-256 مشخص دریافت می‌شود؛ فایل AAR و APKها وارد Git نمی‌شوند.
- اگر Secretها غایب باشند، کلید اشتباه باشد، تست/ساخت شکست بخورد یا نسخه قبلاً منتشر شده باشد، فرایند باید متوقف شود؛ هیچ fallback به کلید debug یا ساخت کلید تازه وجود ندارد.
- انتشار اولیه عمداً **Pre-release** است. قبولی CI به معنی تأیید نصب/بازیابی/اتصال روی گوشی نیست؛ تا پایان آزمون واقعی نباید پایدار اعلام شود.
- artifactهای گزارش تست سه روز نگهداری می‌شوند؛ کلید خصوصی هرگز artifact نمی‌شود و نسخهٔ رمزگشایی‌شده پس از مرحلهٔ امضا از runner پاک می‌شود.

ابتدا شاخهٔ `release/signing-validation-v3` با workflow فقط‌خواندنی، رمز، alias، گواهی و امضای واقعی با کلید خصوصی را بررسی می‌کند؛ سپس تست‌ها، ساخت release و امضای خود APK بررسی می‌شوند. این اجرا چیزی منتشر نمی‌کند.
تنها بعد از دریافت پشتیبان توسط مالک و موفقیت اعتبارسنجی، تگ جدید `v1.19.1` برای انتشار Pre-release ارسال می‌شود.
تگ قبلی `v1.19` حفظ شده اما APK ندارد؛ کلید منتشرنشدهٔ آن به علت نبودن پشتیبان با اجازهٔ صریح مالک جایگزین شد.
این کلید نسل ۳ باید از این پس ثابت بماند. تغییر fingerprint برای دورزدن خطای Secrets ممنوع است.
