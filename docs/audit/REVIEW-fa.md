# گزارش بررسی پرواز ۱.۱۸

**تاریخ بررسی:** ۸ سپتامبر ۲۰۲۶ — ۱۷ شهریور ۱۴۰۵  
**مخزن:** https://github.com/hojjatrad/parvaz  
**نسخهٔ مبنا:** `0c2b08f78bbcd699558894dbeac2c05c53f08614`  
**شاخهٔ محلی گزارش:** `review/v1.18-audit`

## جمع‌بندی

برنامه یک کلاینت اندرویدی Xray با امکانات نسبتاً زیاد است، اما ادعای «پشتیبانی کامل از Clash، Sing-box و همهٔ پنل‌ها» با پیاده‌سازی فعلی سازگار نیست. مهم‌ترین اصلاح فوری، بازگرداندن اعتبارسنجی HTTPS دریافت اشتراک است. پس از آن باید واردکننده‌ها، به‌روزرسانی بدون ازدست‌رفتن هویت سرورها و ناسازگاری‌های فهرست پروتکل‌ها اصلاح شوند.

**در این مرحله هیچ کد اجرایی برنامه اصلاح نشده است.** فقط گزارش، ابزار بازتولید اشکالات و ابزار کنترل فضای کار اضافه شده‌اند. هیچ APK تازه‌ای ساخته یا روی گوشی نصب نشده و هیچ تغییری به گیت‌هاب push نشده است.

## دامنه و اعتبار نتیجه‌ها

- مسیرهای دریافت و پردازش اشتراک، مدل و ذخیرهٔ پروفایل، سازندهٔ کانفیگ Xray، بخش‌هایی از سرویس VPN، تست نشت، هات‌اسپات، تنظیمات ساخت و manifest بررسی شدند.
- آزمایش سبک JVM روی **کد واقعی parser و Profile** اجرا شد: ۱۰ مشاهده تأیید شد؛ یکی نمونهٔ سالم کنترل و ۹ مورد بازتولید محدودیت/ایراد هستند. نتایج در `parser-results.txt` است.
- ابزار آزمایش برای `android.net.Uri` فقط جایگزین کامپایل دارد که هنگام فراخوانی خطا می‌دهد؛ بنابراین این آزمایش، صحت لینک‌های URI روی اندروید را تأیید نمی‌کند. Base64 با پیاده‌سازی استاندارد Java جایگزین شده است.
- مجموعه‌تست‌های موجود Android/Robolectric اجرا نشده‌اند؛ محیط حاضر SDK اندروید، Gradle آماده و هستهٔ native پروژه را ندارد. Java موجود نسخهٔ ۱۱ است، درحالی‌که پروژه سطح زبان ۱۷ می‌خواهد.
- اتصال واقعی، نشت DNS/IPv6، پایداری با خاموش‌شدن صفحه و تغییر شبکه باید روی گوشی و با سرور آزمایشی بررسی شوند. وجود گزینه در رابط به معنی عملکرد تأییدشده نیست.

## فهرست ایرادها و ترتیب پیشنهادی اصلاح

P0: امنیت فوری؛ P1: اتصال/داده/اعتماد به نتیجه؛ P2: سازگاری و نگهداری.

### ۱. P0 — اعتبارسنجی HTTPS اشتراک عملاً خاموش است

**قطعی در کد.** `checkServerTrusted` کاری نمی‌کند و `HostnameVerifier` همیشه true برمی‌گرداند. این رفتار برای همهٔ دریافت‌های HTTPS اشتراک اعمال می‌شود، نه فقط یک پنل با اجازهٔ کاربر. مهاجمِ بین مسیر می‌تواند محتوای اشتراک را جایگزین کند و در سناریوی شنود فعال به URL محرمانهٔ اشتراک دسترسی پیدا کند.

**اصلاح:** حذف trust-all؛ اعتبارسنجی پیش‌فرض سیستم؛ برای گواهی خصوصی، اعتماد محدود به همان میزبان/گواهی با تأیید آگاهانه، نه خاموش‌کردن عمومی بررسی TLS.

**شاهد:** [SubscriptionUpdater.java، خطوط ۵۵–۱۰۱](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/SubscriptionUpdater.java#L55-L101)

### ۲. P1 — دریافت اشتراک محدودیت حجم و سیاست امن redirect ندارد

**قطعی در کد؛ اثر مصرف منابع هنوز روی گوشی اندازه‌گیری نشده.** پاسخ تا انتها در RAM خوانده می‌شود و سقف بایت/تعداد سرور وجود ندارد. redirect از HTTPS به HTTP مسدود نشده است. پایان پنج دور redirect به خطای روشن منتهی نمی‌شود و ممکن است پاسخ خالی برگردد. HTML نیز قبل از parser رد نمی‌شود.

**اصلاح:** سقف قابل تنظیم برای بدنه و تعداد پروفایل، مهلت کلی، بستن منابع در finally/try-with-resources، پذیرش کدهای HTTP مشخص، خطای صریح حلقه/تعداد redirect و منع downgrade پیش‌فرض. خطاهای TLS، 401/403، 429، HTML و اشتراک خالی جدا نمایش داده شوند.

**شاهد:** [SubscriptionUpdater.java، خطوط ۹۹–۱۶۰](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/SubscriptionUpdater.java#L99-L160)

### ۳. P1 — رمز امضای انتشار در سورس عمومی نوشته شده است

**قطعی در تنظیمات ساخت.** رمز و مسیر ثابت keystore در `app/build.gradle` قرار دارند. این به‌تنهایی اثبات افشای کلید خصوصی نیست؛ فایل کلید در فهرست فایل‌های نسخهٔ بررسی‌شده دیده نشد.

**اصلاح:** انتقال اطلاعات امضا به secrets محیط ساخت، بررسی دسترسی و سابقهٔ فایل کلید، پشتیبان امن کلید موجود. کلید امضای برنامه را بی‌برنامه عوض نکنیم، چون نصب به‌روزرسانی روی نسخهٔ قبلی ممکن است قطع شود. تغییر رمز keystore هم جایگزین تعویض کلید خصوصی افشاشده نیست.

**شاهد:** [app/build.gradle](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/build.gradle#L29-L36)

### ۴. P1 — Hysteria2 و TUIC وارد می‌شوند اما وصل نمی‌شوند

**محدودیت صریح کد.** parser آن‌ها را می‌سازد، ولی `ProtocolSupport` آن‌ها را unsupported معرفی می‌کند و builder خطا می‌دهد.

**اصلاح:** فعلاً برچسب «فقط قابل واردکردن؛ هستهٔ فعلی پشتیبانی نمی‌کند» در تمام مسیرها؛ برای اتصال واقعی، بررسی افزودن هستهٔ مناسب مانند sing-box با معماری انتخاب هسته. اندازهٔ APK، مصرف باتری، ABIها، نسخه‌ها و مجوز انتشار باید بررسی شوند. تغییر اسم پروتکل یا تبدیل ظاهری JSON این مشکل را حل نمی‌کند.

**شاهد:** [ProtocolSupport.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/ProtocolSupport.java)

### ۵. P1 — parser مربوط به Clash، YAML واقعی و کامل نیست

**چند حالت بازتولید شد.** parser متن را خط‌به‌خط و با اولین `:` می‌شکند. نگاشت inline مانند `- {name: ..., type: ...}` وارد نمی‌شود. ساختارهای تو‌در‌تو و لیست‌ها به‌درستی مدل نمی‌شوند؛ نام سرویس gRPC از دست می‌رود. Trojan بدون فیلد اختیاری `tls` با security خالی وارد می‌شود، درحالی‌که مسیر لینک مستقیم Trojan پیش‌فرض TLS دارد.

**اصلاح:** YAML parser معتبر با محدودیت عمق/alias/اندازه، schema مشخص برای هر نوع proxy، نگاشت درست `ws-opts`، `grpc-opts`، `reality-opts`، ALPN و پیش‌فرض پروتکل‌ها. قواعد و گروه‌های Clash را نباید وانمود کنیم به‌طور کامل منتقل شده‌اند.

**شاهد:** [ClashParser.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/ClashParser.java)

### ۶. P1 — فهرست پشتیبانی با builder یکسان نیست

**بخشی بازتولید، بخشی بررسی مستقیم.** Clash نوع `ss` را همان `ss` ذخیره می‌کند؛ `ProtocolSupport` آن را مجاز می‌داند، اما builder فقط شاخهٔ `shadowsocks` دارد. نوع `http` نیز در فهرست مجاز است، ولی شاخهٔ ساخت outbound برای آن وجود ندارد. برعکس، `custom` در builder مسیر دارد اما از `isSupported` رد می‌شود و در انتخاب سریع سرور حذف می‌گردد.

**اصلاح:** canonicalization مرکزی نام‌ها و یک جدول قابلیت مشترک میان parser، UI و builder؛ وضعیت JSON سفارشی پس از اعتبارسنجی تعیین شود.

**شاهد:** [XrayConfigBuilder.java، از خط ۶۳۸](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/XrayConfigBuilder.java#L638) و `ProtocolSupport.java`.

### ۷. P1 — تبدیل Sing-box بخشی از تنظیمات را از دست می‌دهد

**حذف password مربوط به TUIC بازتولید شد.** فقط بخشی از فیلدها نگاشت می‌شوند؛ برای نمونه UUID خوانده می‌شود ولی password دوم TUIC در `quicKey` قرار نمی‌گیرد. نگاشت اختصاصی کامل WireGuard، ALPN، بعضی احراز هویت‌ها و تنظیمات اختصاصی پروتکل‌ها وجود ندارد. routing، selector و urltest به مدل اجرای کامل منتقل نمی‌شوند.

**اصلاح:** نگاشت schema‌محور با هشدار دقیق فیلدهای پشتیبانی‌نشده؛ در صورت افزودن هستهٔ sing-box، مسیر اجرای native جدا از تبدیل محدود به Xray داشته باشیم.

**شاهد:** [SingBoxParser.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/SingBoxParser.java)

### ۸. P1 — JSON متفرقه به‌عنوان کانفیگ پذیرفته می‌شود؛ JSON کامل هم کامل اجرا نمی‌شود

**پذیرش JSON صرفاً شامل سهمیه بازتولید شد.** هر شیء JSON که parserهای دیگر آن را تشخیص ندهند می‌تواند یک پروفایل `custom:443` بسازد، حتی بدون outbound. این مهم است چون updater خود پاسخ JSON اطلاعات پنل را می‌شناسد. همچنین builder فقط اولین outbound مناسب را از JSON کامل استخراج می‌کند؛ DNS، routing و وابستگی outboundها به شکل اصلی حفظ نمی‌شوند.

**اصلاح:** تفکیک پاسخ API پنل از config؛ اعتبارسنجی schema و وابستگی tagها؛ انتخاب آگاهانه میان «استخراج سرور» و «اجرای کامل JSON با محدودیت‌های لازم». raw JSON شبکهٔ ناشناخته نباید بی‌هشدار به تنظیمات محلی دسترسی گسترده بدهد.

**شاهد:** [LinkParser.java، خطوط ۱۵۳–۲۰۰](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/LinkParser.java#L153-L200) و [builder، خط ۶۳۸](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/XrayConfigBuilder.java#L638).

### ۹. P2 — تشخیص قالب ورودی ناقص و گزارش خطا کم‌اطلاع است

**آرایهٔ JSON و Clash داخل Base64 بازتولید شد.** تشخیص JSON/YAML قبل از بازکردن Base64 انجام می‌شود و پس از آن تکرار نمی‌شود. آرایهٔ JSON پشتیبانی نشده است. خطاهای تک‌لینک در `parseMany` بدون گزارش به کاربر کنار گذاشته می‌شوند. `valid` عمدتاً فقط آدرس و بازهٔ پورت را بررسی می‌کند؛ صحت UUID، کلید و تنظیمات لازم پروتکل بررسی جامع ندارد.

**اصلاح:** پاک‌سازی BOM و فاصله، تشخیص چندمرحله‌ای محدود، پشتیبانی آرایه، validation پروتکل‌محور، نتیجهٔ ساختاریافته شامل تعداد سالم/تکراری/ردشده و شمارهٔ ورودی، بدون نمایش رمز یا URL محرمانه.

**شاهد:** [LinkParser.java، خطوط ۳۹–۱۰۰](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/LinkParser.java#L39-L100)

### ۱۰. P1 — refresh اشتراک، هویت سرورها را از نو می‌سازد و اتمیک نیست

**قطعی در مسیر کد؛ از‌دست‌رفتن وضعیت روی گوشی هنوز آزمایش نشده.** ابتدا تمام پروفایل‌های اشتراک حذف و ذخیره می‌شوند، بعد پروفایل‌های تازه با UUID داخلی تازه اضافه و مجدداً ذخیره می‌شوند. بنابراین selected_profile، پینگ و سایر اطلاعات متصل به ID ممکن است دیگر به سرور موجود اشاره نکنند. حذف و اضافه یک تراکنش واحد نیست و refreshهای هم‌زمان می‌توانند بین آن‌ها وارد شوند.

**اصلاح:** diff/upsert اتمیک، حفظ ID برای سرور هم‌ارز، حفظ آخرین نسخهٔ سالم در خطا، جلوگیری از اجرای هم‌زمان refresh و آزمون crash بین مراحل. خالی‌شدن معتبر اشتراک باید از خطای دریافت/parse تفکیک شود.

**شاهد:** [SubscriptionUpdater_4.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/SubscriptionUpdater_4.java#L35-L49) و [ProfileStore.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/store/ProfileStore.java#L146-L156).

### ۱۱. P1 — تشخیص تکراری‌ها می‌تواند کانفیگ متفاوت را حذف کند

**قطعی در مقایسهٔ کد.** فقط protocol، address، port، uuid، path و network مقایسه می‌شوند. تفاوت SNI، Reality public key/short ID، flow، رمز دوم SOCKS/TUIC و مالکیت اشتراک در مقایسه نیست. مقایسه نیز سراسری است، بنابراین یک سرور مشترک میان دو اشتراک ممکن است فقط متعلق به یکی ذخیره شود.

**اصلاح:** fingerprint معنایی همهٔ فیلدهای مؤثر اتصال و مدل مالکیت چنداشتراکی یا dedup در محدودهٔ اشتراک. پارامتر محرمانه در گزارش fingerprint چاپ نشود.

**شاهد:** [ProfileStore.java، خطوط ۹۳–۱۳۴](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/store/ProfileStore.java#L93-L134)

### ۱۲. P1 — Worker ممکن است خطای refresh را موفق اعلام کند

**قطعی در کد.** callback خطا را فقط log می‌کند و latch را آزاد می‌کند؛ `doWork` پس از آزادشدن latch همیشه success می‌دهد. پاسخ خالی parser هم خطای روشن ثبت نمی‌کند. در نتیجه backoff/retry در بخشی از خطاهای واقعی عمل نمی‌کند. thread ایجادشده نیز با پایان انتظار به‌صورت ساختاریافته لغو نمی‌شود.

**اصلاح:** انتقال نتیجهٔ واقعی به Worker، تفکیک خطای موقت و دائمی، لغو درخواست هنگام توقف، گزارش نتیجه به‌ازای هر اشتراک.

**شاهد:** [SubscriptionWorker.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/SubscriptionWorker.java)

### ۱۳. P1 — پل هات‌اسپات با پورت پروکسی داخلی تداخل دارد

**اشکال ساختاری قطعی؛ اجرای روی دستگاه انجام نشده.** Xray روی `127.0.0.1:10809` گوش می‌دهد، اما پل LAN نیز روی همهٔ رابط‌ها پورت 10809 را bind می‌کند و به `127.0.0.1:10809` فوروارد می‌کند. در حالت عادی این bind با listener موجود تداخل دارد؛ اگر listener داخلی نباشد، پل می‌تواند اتصال را به خودش برگرداند. علاوه بر این، authentication ندارد و تعداد threadها محدود نیست. این پیاده‌سازی اشتراک‌گذاری تمام ترافیک هات‌اسپات نیست، بلکه قرار است یک پل HTTP proxy باشد.

**اصلاح:** پورت LAN جدا، bind به رابط موردنظر، احراز هویت و محدودیت اتصال/thread، مدیریت صحیح شکست start، توضیح نیاز به تنظیم proxy در دستگاه دوم. عدم دسترسی دیگران روی Wi-Fi مشترک آزمایش شود.

**شاهد:** [HotspotProxyManager.java، خطوط ۴۱–۶۵](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/HotspotProxyManager.java#L41-L65) و [XrayConfigBuilder.java، خطوط ۳۰۵–۳۲۸](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/config/XrayConfigBuilder.java#L305-L328).

### ۱۴. P1 — تست نشت می‌تواند اطمینان کاذب یا هشدار اشتباه بدهد

**قطعی در منطق؛ نشت واقعی اثبات نشده.** `allPassed()` فقط نبود FAIL را می‌سنجد و UNKNOWN را شکست محسوب نمی‌کند. تست IPv6 هر آدرس IPv6 قابل دریافت را نشت می‌نامد، بدون اثبات اینکه از تونل خارج شده؛ خطای شبکه را نیز PASS می‌گیرد. تست DNS جغرافیای resolver و ایرانی‌بودن را مبنا قرار می‌دهد و از پارامتر IP خروجی استفاده نمی‌کند؛ این برای اثبات مسیر DNS کافی نیست.

**اصلاح:** سه‌حالتهٔ واقعی موفق/نشت/نامشخص، اندازه‌گیری کنترل‌شدهٔ مسیرها، مقایسهٔ خروجی تونل با baseline و DNS authoritative دارای شناسهٔ آزمایش. خطای سرویس تست هرگز «امن است» ترجمه نشود.

**شاهد:** [LeakTester.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/core/LeakTester.java#L58)

### ۱۵. P2 — ورود کانفیگ از برنامه‌های دیگر کامل نیست

**قطعی در مسیر بررسی‌شده.** `handleIntent` فقط `intent.getData()` را می‌خواند، نه متن `ACTION_SEND/EXTRA_TEXT` یا فایل اشتراک. schemeهای `wg`، `wireguard` و `socks5` در فیلتر manifest وجود ندارند، با اینکه parser آن‌ها را می‌شناسد. URL اشتراک مسیر جداگانه‌ای در UI دارد و ورود عمومی آن را خودکار دریافت نمی‌کند.

**اصلاح:** یک Import Router برای paste، QR، share text، content URI، فایل و URL؛ پشتیبانی امن و محدود از deep-linkهای موردنیاز کلاینت‌ها. لینک صفحهٔ مدیریت پنل با لینک اشتراک مشترک یکی نیست.

**شاهد:** [MainActivity.java، از خط ۱۱۲۱](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/MainActivity.java#L1121) و [AndroidManifest.xml](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/AndroidManifest.xml#L25-L47).

### ۱۶. P2 — حفاظت دادهٔ داخلی و بکاپ نیازمند تقویت است

**قطعی در ذخیره‌سازی، نه اثبات دسترسی از بیرون.** پروفایل‌ها و URL اشتراک به‌صورت JSON در SharedPreferences خصوصی برنامه ذخیره می‌شوند. sandbox اندروید و رمزگذاری دستگاه لایهٔ حفاظت دارند، اما رمزگذاری اختصاصی مبتنی بر Keystore در این مسیر نیست. بکاپ خروجی AES-GCM دارد که نکتهٔ مثبت است؛ بااین‌حال انتخاب خودکار PBKDF2-SHA256 یا fallback SHA1 در قالب بکاپ ثبت نشده و بازیابی میان محیط‌هایی با الگوریتم در دسترس متفاوت بالقوه مشکل‌ساز است.

**اصلاح:** طراحی تهدید، رمزگذاری اطلاعات حساس با Android Keystore و برنامهٔ مهاجرت، ثبت KDF/iterations در نسخهٔ جدید بکاپ و آزمون بازیابی بین نسخه‌های اندروید. کانفیگ‌ها، بکاپ و لاگ حساس نباید به مخزن عمومی بروند.

**شاهد:** [ProfileStore.java، خط ۱۹۹](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/store/ProfileStore.java#L199) و [BackupCrypto.java](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/src/main/java/com/parvaz/tunnel/store/BackupCrypto.java).

### ۱۷. P2 — ساخت و آزمون پروژه قابل‌انتقال و خودکار نشده است

**قطعی در فایل‌های بررسی‌شده.** Gradle Wrapper و workflow CI در درخت این نسخه نیست. مسیرهای `/opt/pb` و مسیر ثابت keystore وابستگی محیطی ایجاد کرده‌اند. lint انتشار غیرفعال است. bootstrap دانلودهای بدون checksum دارد و بخشی از سورس بازسازی‌شده از decompile است؛ این‌ها نگهداری را دشوار می‌کنند. پروژه چند مجموعه‌تست دارد، پس تعبیر «هیچ تستی ندارد» درست نیست.

**اصلاح:** Gradle Wrapper با checksum، مستند ساخت تمیز، pin و بررسی هش هسته، GitHub Actions برای unit/lint/build، fixtureهای parser از پنل‌ها و آزمون اتصال مجزا. فعال‌سازی تدریجی lint همراه با baseline، نه خاموش‌کردن سراسری.

**شاهد:** [app/build.gradle](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/app/build.gradle) و [tools/setup_android.sh](https://github.com/hojjatrad/parvaz/blob/0c2b08f78bbcd699558894dbeac2c05c53f08614/tools/setup_android.sh).

### ۱۸. P2 — فایل‌های انتشار حجیم داخل خود Git نگهداری شده‌اند

در درخت نسخهٔ مبنا سه ZIP مربوط به ۱.۱۶، ۱.۱۷ و ۱.۱۸ وجود دارد؛ مجموع آن‌ها حدود **۱۲۳٫۳ مگابایت ده‌دهی** است. این در کنار GitHub Releases حجم clone و تاریخچه را بی‌جهت زیاد می‌کند. حذف فایل از آخرین commit به‌تنهایی آن را از تاریخچه حذف نمی‌کند.

**اصلاح:** سورس/تست/مستند در Git؛ APK/ZIP و checksum در Releases؛ retention محدود برای artifactهای CI. ابتدا وجود و صحت فایل‌های Releases تأیید شود. پاک‌سازی تاریخچه و force-push فقط با تأیید جداگانهٔ مالک و پشتیبان انجام شود. در این بررسی هیچ فایل remote یا تاریخچه‌ای حذف نشده است.

## مواردی که هنوز باید روی دستگاه بررسی شوند

این‌ها «باگ ثابت‌شده» نیستند، بلکه برنامهٔ آزمون‌اند:

- حفظ مسدودبودن ترافیک با Kill Switch هنگام crash کامل فرایند، revoke، restart و تعویض سرور؛ تفاوت آن با Always-on و گزینهٔ سیستمی Block connections without VPN.
- DNS و IPv6 در حالت روشن/خاموش، bypass LAN و split tunneling، بدون نتیجه‌گیری صرف از وجود یا نبود route.
- تغییر Wi-Fi به دیتای موبایل، حالت هواپیما، Doze، خاموشی صفحه و محدودیت باتری سازندگان.
- server endpoint با IPv6، به‌ویژه تولید endpoint مربوط به WireGuard که با اتصال مستقیم address و `:` و port ساخته می‌شود.
- URIهای دارای `+`، `%25`، `%2B` و متن فارسی؛ استفاده از `getUserInfo/getFragment` سپس `URLDecoder` خطر decode دوباره دارد و باید روی Android واقعی/Robolectric آزموده شود.
- transportهای جدید یا اختصاصی پنل‌ها، پارامترهای XHTTP/Reality و نسخهٔ دقیق هسته؛ پشتیبانی از نام پروتکل تضمین حفظ همهٔ گزینه‌ها نیست.

## طرح پشتیبانی از پنل‌ها و انواع لینک

### اصل طراحی

**پنل ≠ قالب اشتراک ≠ پروتکل ≠ هستهٔ اجرا.** دو پنل مختلف ممکن است خروجی یکسان بدهند و دو نسخه از یک پنل خروجی متفاوت تولید کنند. هدف باید «سازگاری آزموده‌شده با قالب‌های مشخص» باشد، نه وعدهٔ غیرقابل اثبات «هر لینکی از هر پنلی».

### دامنهٔ پیشنهادی مرحلهٔ اول

- پنل‌های هدف برای fixture و آزمون: Marzban، 3x-ui/X-UI، Hiddify، Marzneshin، V2Board/XBoard؛ اولویت دقیق با نمونهٔ کاربر تعیین شود.
- لینک‌های مستقیم: `vless://`، `vmess://`، `trojan://`، `ss://`، `socks://`، `socks5://`، `wg://` و `wireguard://`.
- ورودی اشتراک: HTTPS، متن ساده، Base64 استاندارد و URL-safe، JSON تکی/آرایه، Clash/Mihomo YAML و Sing-box JSON در محدودهٔ نگاشت مستند.
- metadata: نام اشتراک، سهمیه/مصرف/انقضا از هدر و پاسخ‌های مشخص؛ خروجی اختصاصی پنل فقط از adapter مستند، بدون نیاز به رمز پنل مدیر.
- Hysteria2/TUIC: پذیرش همراه هشدار در مرحلهٔ اول؛ اتصال فقط پس از ادغام و آزمون هستهٔ مناسب.
- فایل WireGuard `.conf`، pluginهای Shadowsocks، deep-linkهای کلاینت‌های دیگر و فرمت‌های اختصاصی در backlog جدا؛ در نسخهٔ فعلی به‌عنوان پشتیبانی کامل معرفی نشوند.

### مسیر پیشنهادی پردازش

`ورودی کاربر → تشخیص URL/فایل/متن → دریافت امن → تشخیص قالب → parser → مدل مشترک بدون حذف خاموش فیلد → اعتبارسنجی قابلیت هسته → پیش‌نمایش نتیجه → ذخیرهٔ اتمیک`

URLهای اشتراک حامل توکن‌اند. در UI، log، screenshot آزمون و fixture باید مخفی یا ساختگی باشند. دریافت یک صفحهٔ HTML فروش/مدیریت نباید به‌عنوان اشتراک موفق ثبت شود. User-Agent فعلی ثابت است؛ انتخاب قالب یا header موردنیاز پنل باید محدود، قابل توضیح و آزموده‌شده باشد، نه تغییر کورکورانه تا پاسخی دریافت شود.

### معیار پذیرش

۱. ورودی سالم دقیقاً پارامترهای اتصال را حفظ کند. ۲. ورودی خراب دلیل قابل‌فهم بدهد. ۳. ورودی مخلوط، سرور سالم را نگه دارد و تعداد ردشده را گزارش کند. ۴. خطای دریافت/parse فهرست سالم قبلی را حذف نکند. ۵. refresh هویت و انتخاب سرور را حفظ کند. ۶. UUID/رمز واقعی در لاگ نیاید. ۷. موفقیت import با موفقیت اتصال اشتباه نشود. ۸. TLS نامعتبر پیش‌فرض رد شود. ۹. فایل بزرگ/redirect حلقه‌ای حافظه یا thread نامحدود مصرف نکند.

## نقشهٔ اجرای مشترک

- **بستهٔ A — امنیت و پایه:** موارد ۱، ۲ و ۳؛ جدول یکپارچهٔ پروتکل‌ها و رفع SS/HTTP/custom؛ تست‌های رگرسیون.
- **بستهٔ B — ورودی چندپنلی:** YAML واقعی، JSON و Base64، validation، Import Router و fixtureهای بدون اطلاعات واقعی.
- **بستهٔ C — اشتراک پایدار:** diff/upsert اتمیک، dedup درست، خطای Worker و حفظ سهمیه/انتخاب سرور.
- **بستهٔ D — قابلیت‌های شبکه:** اصلاح پل LAN و تست نشت؛ آزمون Kill Switch، IPv6، باتری و تغییر شبکه روی گوشی.
- **بستهٔ E — هسته و انتشار:** تصمیم sing-box برای Hysteria2/TUIC، CI و ساخت قابل‌تکرار، انتشار آزمایشی سپس پایدار.

## گیت‌هاب و مدیریت فضا

- مخزن عمومی برای خواندن دسترسی اضافه نمی‌خواهد؛ برای push هنوز دسترسی نوشتن در اختیار این محیط نیست. شاخه و patch محلی برای انتقال آماده می‌شوند؛ ایجاد شاخهٔ remote یا Pull Request انجام نشده است.
- رمز، PAT یا کلید خصوصی را در متن چت ارسال نکنید. در صورت وجود اتصال امن GitHub در محیط، مجوز فقط برای همین مخزن و حداقل سطح لازم باشد. راه بدون تحویل توکن: اعمال patch توسط مالک و push از دستگاه خودش.
- clone سبک با sparse checkout ساخته شد؛ `release/` و فایل‌های نصبی وارد working tree نشده‌اند. نسخهٔ اولیهٔ موقت و بدون تغییر پس از تأیید یکسان‌بودن commit با clone سبک حذف شد. clone سبک پیش از افزودن گزارش حدود ۸ مگابایت شامل Git و سورس بود.
- ابزار `tools/workspace_guard.py` اضافه شد. پیش‌فرض فقط گزارش می‌دهد. با `--clean` و فقط وقتی مصرف دیسک به ۸۰٪ برسد یا فضای آزاد زیر ۳ GiB باشد، پوشه‌های تولیدی مجاز این پروژه (`.cache/audit`، `app/build` و `build`) را بررسی و در صورت untracked بودن حذف می‌کند. سورس، `.git`، کلیدها، فایل‌های انتشار، وابستگی native و commitهای push‌نشده را حذف نمی‌کند.
- این ابزار باید **بین عملیات ساخت** اجرا شود، نه هم‌زمان با آن. پایش دائمی در زمان بسته‌بودن گفتگو ایجاد نشده و تضمین پایش خارج از اجرای ابزار وجود ندارد. اگر فایل مجاز کافی برای آزادسازی فضا نباشد، دانلود/ساخت بزرگ باید متوقف شود، نه اینکه اطلاعات کاربر پاک شود.
- برای کم‌حجم ماندن snapshot، `.cache/` نادیده گرفته شده است. فقط کد و نتیجهٔ کوچک آزمایش‌ها نگهداری می‌شود.

## برای شروع مرحلهٔ اصلاح چه لازم است؟

۱. تأیید شروع بستهٔ A. ۲. نام پنل‌های مورد استفاده و نسخهٔ اندروید/مدل گوشی. ۳. در مرحلهٔ fixture، نمونهٔ ساختگیِ خروجی یا نمونهٔ پاک‌سازی‌شده با دامنه، UUID، رمز و توکن جایگزین‌شده؛ فعلاً لینک واقعی و فعال لازم نیست. ۴. برای انتشار نصب‌شدنی، مسیر امن استفاده از کلید امضای قبلی؛ خود کلید نباید به مخزن عمومی یا چت منتقل شود.
