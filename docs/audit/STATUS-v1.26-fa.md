# پیگیری اصلاحات 1.26 — هنوز منتشر نشده

این سند وضعیت شاخهٔ توسعه است، نه تأیید انتشار APK یا پایان همهٔ آزمون‌ها. آخرین نسخهٔ عمومی در زمان نگارش همچنان **1.25 / code 26** است. مشکل زیادشدن اتصال‌ها را کاربر در همان نسخه تأیید کرده که رفع شده؛ آن مسیر بازطراحی نشده است.

## تطبیق با گزارش اولیه

| مورد | وضعیت پیاده‌سازی و حدود ادعا |

## خطاهایی که آزمون‌ها پیدا کردند

- تفاوت escape کاراکتر `/` در JSON اندروید و خوانندهٔ YAML میهومو: مسیر serialization اصلاح شد و راه‌اندازی هر دو موتور روی API 29 در اجرای `34353616632` موفق بود؛ کل اجرا به‌علت مرحلهٔ API 34 موفق نبود.
- Android 14: sing-box در outbound مستقیم، مانیتور رابطِ ناموجود را dereference می‌کرد. patch محدود و مشخص برای این مورد افزوده شده است؛ مجوز root یا دسترسی به فایل‌های سیستمی درخواست نمی‌شود. نتیجهٔ آزمونِ پس از patch هنوز باید ثبت شود.
- lint: localeهای قابل انتخاب برنامه فارسی/انگلیسی هستند؛ محدودیت زبان ساخت با همین واقعیت هماهنگ شد. مسیرها و شناسه‌های انیمیشن متن ترجمه‌پذیر نیستند. نتیجهٔ کامل lint نهایی هنوز در حال بررسی است.

## شواهد فعلی، نه گواهی انتشار

- تست‌های host و 25 تست ابزار انتشار موفق‌اند.
- ساخت debug، واحدهای Android و بررسی R8 در `34355020998` موفق بوده‌اند؛ این ساخت پیش از آخرین patch هسته است.
- `34354829669`: تبادل TCP/UDP، احراز هویت، رد SNI نادرست برای HY2/TUIC و مسیریابی/گروه کامل Mihomo با fixture موفق؛ مرحلهٔ Android 14 شکست داشت.
- `34353616609`: پروب Android 10/14 مربوط به امضای آرشیو و Keystore موفق؛ این پروب اتصال کامل VPN نیست.
- `34355020996`: سورس متناظر حدود 477 MB ساخته شد، اما lint شکست داشت و APK انتشار تأیید نشده است.
- نسخهٔ 1.26 تا عبور از دروازه‌های انتشار نباید به‌عنوان آپدیت پایدار معرفی شود.

## محدودیت‌هایی که باید روشن بمانند

پیکربندی کامل فقط از منبع قابل‌اعتماد وارد شود. قواعد DIRECT صریح حفظ می‌شوند. listener/TUN و مدیریت رابط را Android/پرواز کنترل می‌کنند؛ سیاست‌های وابسته به فرایند و رابط دسکتاپ معادل‌سازی نمی‌شوند. fake-IP میهومو برای این مسیر به پاسخ IP واقعی تبدیل می‌شود. سرویس‌های مدیریتی/اجرایی حذف یا رد می‌شوند.

قبل از ارتقا پشتیبان رمزدار بگیرید. حذف برنامه/داده می‌تواند کلید دستگاه را از بین ببرد؛ این کلید با کلید امضای انتشار فرق دارد. خروجیِ در حال انتخاب مقصد در حافظه است؛ اگر Activity بازسازی شود و خروجی از دست برود، ذخیره موفق اعلام نمی‌شود و باید دوباره خروجی گرفت. بازیابی رکوردها و تنظیمات دو commit جدا دارند؛ ادعای تراکنش چندفایلی نداریم.

هنوز آزمون گوشی واقعی، ارتقای درجا، پنل‌های خصوصی، قطع ناگهانی فرایند، جابه‌جایی Wi-Fi/mobile، Doze/باتری، Kill Switch و نشت واقعی انجام نشده است. نتیجهٔ شبیه‌ساز یا fixture جای آن‌ها را نمی‌گیرد. بدون این شواهد نباید «همهٔ دستگاه‌ها و همهٔ پنل‌ها تضمین‌شده‌اند» گفته شود.
