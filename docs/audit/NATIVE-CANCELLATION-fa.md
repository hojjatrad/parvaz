# آزمون تکمیلی لغو راه‌اندازی و پاک‌سازی هسته‌ها

این مرحله فقط آزمون و گزارش را تغییر می‌دهد؛ کد اجرایی `app/` با تگ منتشرشدهٔ **v1.26.1** یکسان است. نسخه، APKها و کلید دائمی تغییر نکرده‌اند. افزودن آزمون به‌تنهایی دلیل انتشار APK تازه نیست.

## سناریوهای افزوده‌شده

1. **درخواست دیررس روی نشست بسته:** متد راه‌اندازی باید قبل از ایجاد فرزند خطای صریح بدهد و هیچ Process به نشست بسته متصل نشود.
2. **لغو درخواست در صف راه‌اندازی:** executor آزمایشی موقتاً با latch نگه داشته می‌شود؛ پس از رسیدن درخواست به انتظار Future، رشتهٔ درخواست‌دهنده قطع می‌شود. آزادشدن ظرفیت، حذف پوشهٔ خصوصی، تخلیهٔ درخواست لغوشده و اتصال واقعی درخواست بعدی بررسی می‌شوند.
3. **لغو انتظار ظرفیت:** سه هستهٔ واقعی ظرفیت را پر می‌کنند؛ درخواست چهارم هنگام انتظار لغو می‌شود. نباید ظرفیتی را که نگرفته آزاد کند یا هسته‌های فعال را قطع کند. دو بار بستن یک نشست هم نباید ظرفیت اضافی ایجاد کند؛ سپس جایگزینی واقعی آزموده می‌شود.
4. **چهار چرخهٔ راه‌اندازی/توقف:** دو موتور به‌نوبت راه‌اندازی می‌شوند. پس از TCP واقعی و توقف، خروج فرزند از طریق Process.waitFor، حذف پوشه و فایل CA موقت، پاک‌شدن رمز نشست، آزادشدن پورت و بازگشت ظرفیت بررسی می‌شوند.

Reflection فقط روی کلاس خود پروژه، داخل APK کمکی انجام می‌شود؛ API مخفی Android، قلاب آزمایشی در برنامهٔ اصلی یا دادهٔ خصوصی کاربر در کار نیست. سناریوی انتظار با مشاهدهٔ قاب پشتهٔ مشخص همگام می‌شود، نه حدس‌زدن با تأخیر ثابت.

گزارش CI اکنون پیام‌های موفقیت را در یک اعلان برای هر SDK جمع می‌کند تا سقف تعداد اعلان‌های GitHub شواهد را حذف نکند؛ تعداد تست/خطا/شکست XML نیز ثبت می‌شود.

## تصمیم پس از آزمون

هر چهار سناریوی تازه روی هر دو SDK موفق شدند؛ آزمون‌های قبلی TLS سخت‌گیرانه، TCP/UDP، احراز هویت و چرخهٔ عمر نیز دوباره گذشتند. در این محدوده ایراد تازه‌ای بازتولید نشد.

Git treeهای `app/`، `tools/native/` و `tools/release/` با تگ v1.26.1 برابرند؛ در این مرحله کد اجرایی یا ابزار انتشار تغییر نکرده است. کانال عمومی همچنان v1.26.1 است و اندازه/digest هر چهار asset با رکورد تأییدشدهٔ انتشار برابر مانده‌اند. بنابراین APK یا تگ جدید ساخته نشد و نسخه‌های قبلی بازنویسی نشدند.

[رکورد ماشین‌خوان](../releases/v1.26.1-verification.json) شامل SHA کد آزمون، درخت‌های یکسان و تعداد موارد هر SDK است.

## حدود ادعا

این‌ها آزمون‌های برنامهٔ کمکی روی شبیه‌ساز x86_64 هستند؛ جای گوشی ARM، برنامهٔ کامل TUN، نصب درجا، Kill Switch، نشت DNS/IPv6، جابه‌جایی شبکه یا Doze/باتری را نمی‌گیرند. لغوِ در صف و انتظار ظرفیت از لغو دقیقاً داخل فراخوانی native ساخت فرایند متفاوت است؛ این مرحله آن نقطهٔ داخلی را به‌طور مستقل تزریق خطا نمی‌کند. حفظ پوشه‌های پیشین در مقایسهٔ baseline عمداً انجام می‌شود تا آزمون، حذف عمومی فایل‌های دیگر را موفقیت تلقی نکند.
