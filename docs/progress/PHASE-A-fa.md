# پرواز — نتیجهٔ مرحلهٔ اول اصلاحات

> این گزارش مربوط به مرحلهٔ A است. آخرین تغییرات و وضعیت فعلی در [گزارش مرحلهٔ B](PHASE-B-fa.md) آمده است.

**تاریخ:** ۸ سپتامبر ۲۰۲۶

**هدف اعلام‌شدهٔ کاربر:** استفاده از پنل‌های مختلف روی اندروید ۱۰ و بالاتر

**شاخهٔ محلی:** `fix/subscription-foundation-android10`

**مبنای نسخهٔ منتشرشده:** `0c2b08f`، نسخهٔ ۱.۱۸

> وضعیت: کد آزمایشی و تست‌شده در JVM؛ هنوز APK تازه ساخته نشده، آزمون گوشی انجام نشده و هیچ تغییر تازه‌ای به GitHub push نشده است. این سند جایگزین ادعای آماده‌بودن نسخهٔ انتشار نیست.

## چه چیزهایی اصلاح شد؟

### ۱. دریافت اشتراک با امنیت بیشتر

- trust-all و تأیید همیشگی نام میزبان حذف شد؛ HTTPS از اعتبارسنجی پیش‌فرض سیستم استفاده می‌کند.
- تغییر مسیر HTTPS به HTTP ممنوع شد؛ حلقه و بیش از پنج redirect خطای مشخص می‌دهد.
- بدنهٔ دانلود و دادهٔ بازشده از gzip سقف **۵ MiB** دارند؛ ورودی parser هم سقف طول و **۵۰۰۰ پروفایل** دارد.
- خطاهای HTTP، پاسخ خالی، صفحهٔ ورود HTML، خطای TLS و بزرگ‌بودن داده از هم تفکیک شدند.
- پیام خطای دانلود شامل URL محرمانه، توکن یا متن خام خطای شبکه نیست.
- اتصال و streamها در مسیر موفق و خطا بسته می‌شوند؛ timeout اتصال/خواندن و بودجهٔ زمانی ۶۰ ثانیه‌ای بررسی می‌شود. این بودجه، تضمین قطع سختِ DNS یا همهٔ عملیات مسدودشوندهٔ سیستم در ثانیهٔ ۶۰ نیست.
- هدر سهمیه از یک مبدأ به مبدأ متفاوت در redirect منتقل نمی‌شود؛ gzip و هدرهای سهمیهٔ سازگار همچنان پشتیبانی می‌شوند.

**تغییر رفتاری مهم:** پنلی با گواهی نامعتبر، خودامضا یا نام میزبان اشتباه دیگر با خاموش‌کردن امنیت پذیرفته نمی‌شود. باید گواهی پنل اصلاح شود. راه اعتماد محدود به گواهی خصوصی با رابط تأیید کاربر هنوز ساخته نشده است.

**محدودیت صریح:** برای نشکستن اشتراک‌های قدیمی، اگر خود URL اولیه `http://` باشد همچنان پذیرفته می‌شود؛ این اتصال رمزگذاری‌شده یا محرمانه نیست. الزام HTTPS و هشدار/تأیید HTTP در رابط، کار مرحلهٔ بعد است. این را با ممنوع‌بودن downgrade از HTTPS اشتباه نگیریم.

### ۲. هماهنگی پروتکل‌ها

- نام‌های `ss`، `socks5`، `wg` و `hy2` به نام استاندارد تبدیل می‌شوند. مدل، فهرست قابلیت و builder از منطق مشترک استفاده می‌کنند.
- Shadowsocks واردشده از Clash اکنون به شاخهٔ درست builder می‌رود؛ پروفایل‌های ذخیره‌شده با نام مستعار نیز هنگام normalize اصلاح می‌شوند، بدون تغییر شناسهٔ داخلی آن‌ها در این مسیر.
- شاخهٔ تولید HTTP outbound اضافه و نگاشت نام کاربری/رمز HTTP و SOCKS در ورودی Sing-box اصلاح شد. این به معنی افزودن تشخیص لینک مستقیم HTTP proxy در Import Router نیست؛ URL اشتراک و HTTP proxy هنوز باید جدا مدیریت شوند.
- پروفایل custom معتبر در بررسی قابلیت پذیرفته می‌شود؛ custom خراب از انتخاب قابلیت رد می‌شود.
- Hysteria2/TUIC همچنان **غیرقابل‌اتصال با هستهٔ فعلی** معرفی می‌شوند؛ صرف اصلاح parser باعث پشتیبانی هسته نشده است.

### ۳. ورودی‌های چندقالبی

- آرایهٔ کانفیگ JSON، Base64 حاوی JSON یا YAML و BOM ابتدای متن وارد مسیر صحیح می‌شوند.
- JSON صرفاً شامل اطلاعات پنل/حجم دیگر سرور جعلی `custom:443` ایجاد نمی‌کند.
- JSON خام بدون outbound ساختاری معتبر و کانفیگ صرفاً direct/block رد می‌شود؛ builder هم fallback خطرناک به نخستین outbound دلخواه یا شیء متفرقه ندارد.
- تشخیص Sing-box به ساختار outbound وابسته شده، نه صرف وجود کلمهٔ `server` در هر بخش متن.
- Trojan در Clash پیش‌فرض TLS دارد؛ رمز دوم TUIC در مدل ورودی Sing-box حفظ می‌شود.
- JSON با عمق بیش‌ازحد و مجموعه‌های بیش‌ازحد بزرگ رد می‌شوند؛ فهرست بیش از حد مجاز به‌صورت ناقص برگردانده نمی‌شود.
- پاسخ بدون کانفیگ شناخته‌شده در updater دیگر بی‌سروصدا موفق تلقی نمی‌شود و به مرحلهٔ حذف/افزودن پروفایل نمی‌رسد. بااین‌حال Worker هنوز باید در مرحلهٔ بعد نتیجهٔ callback را به retry/success صحیح تبدیل کند.

**هنوز کامل نیست:** parser فعلی Clash هنوز YAML parser کامل نیست؛ mappingهای inline و همهٔ ساختارهای nested پشتیبانی نشده‌اند. نگاشت Sing-box نیز کامل نشده است. JSON سفارشی هنوز مسیر «استخراج یک outbound» دارد، نه اجرای همهٔ routing/DNS/گروه‌ها و وابستگی‌های کانفیگ اصلی. اعتبارسنجی جدید ساختاری است، نه اثبات صحت همهٔ credentialها و transportها در Xray.

### ۴. امنیت امضای برنامه

- رمز و مسیر ثابت کلید انتشار از `app/build.gradle` و `tools/sign.sh` حذف شد.
- اطلاعات امضا از چهار متغیر محیطی امن دریافت می‌شود؛ اسکریپت امضا رمز را به‌صورت متن آشکار در آرگومان apksigner نمی‌گذارد.
- برای بسته‌بندی release، بررسی وجود تنظیمات امضا اضافه شد؛ debug/test نباید نیاز به کلید انتشار داشته باشد.
- کلید قبلی عوض نشده و هیچ کلید انتشار واقعی در اختیار محیط بررسی نیست.

**توجه:** رمز قدیمی هنوز در تاریخچهٔ عمومی Git وجود دارد؛ حذف از سورس جدید تاریخچه را پاک نمی‌کند. کلید خصوصیِ افشاشده نیز با تغییر رمز keystore امن نمی‌شود. بازنویسی تاریخچه، حذف remote یا تعویض کلید بدون تأیید انجام نشده است. توضیح ساخت در `docs/BUILD-SECURITY.md` است.

## چه تست‌هایی اجرا شد؟

فرمان:

```bash
bash tools/audit/run.sh
```

نتیجهٔ ثبت‌شده در `docs/audit/phase-a-results.txt`:

- **۳۵ assertion پردازش ورودی و ساخت outbound** روی کلاس‌های واقعی پروژه.
- **۶۳ assertion دریافت HTTP و TLS**؛ شامل سیاست redirect، محدودیت حجم، gzip، خطا، بستن منابع و سه سناریوی TLS واقعی روی سرور loopback.
- در TLS واقعی: گواهی خودامضای نامطمئن رد شد؛ گواهی آزمایشیِ مورد اعتماد با نام صحیح پذیرفته شد؛ همان گواهی با نام میزبان اشتباه رد شد. اعتماد گواهی فقط به اتصال تست تزریق شد، نه به تنظیمات سراسری یا برنامه.
- مجموع مجموعهٔ آزمون: **۹۸ assertion موفق**. بررسی جداگانهٔ shell نیز نشان داد اسکریپت امضا بدون secret اجرا نمی‌شود.

### مرز اعتبار تست‌ها

این تست‌ها روی Java 11 محیط بررسی اجرا شده‌اند. Android Uri، SharedPreferences و Context با جایگزین‌های محدود تست/کامپایل حضور دارند؛ ذخیره‌سازی واقعی، lifecycle، routing جغرافیایی و native core آزمایش نشده‌اند. تست‌های TLS از trust store دسکتاپ استفاده می‌کنند، نه trust store اندروید. هیچ اشتراک واقعی کاربر یا پنل زنده‌ای در این آزمایش‌ها استفاده نشده است.

**ساخت کامل Android/Gradle، اجرای مجموعهٔ Robolectric موجود، امضای release و اتصال روی گوشی هنوز انجام نشده‌اند.** تغییر Gradle بررسی متنی شده ولی اجرای taskهای Android آن هنوز تأیید نشده است. ابزار تست قدیمی فقط عیب‌ها را بازتولید می‌کرد؛ ابزار فعلی برای اصلاح‌های این مرحله assertion صحیح دارد. خروجی قدیمی در گزارش نسخهٔ مبنا حفظ شده است.

## اندروید ۱۰ به بالا

هدف آزمون دستگاه از Android 10 / API 29 شروع می‌شود. حداقل SDK فعلی پروژه عمداً از ۲۴ به ۲۹ تغییر نکرده تا پشتیبانی قبلی بی‌دلیل حذف نشود؛ این به معنی آزموده‌شدن Android 7 نیست. versionCode/versionName هم فعلاً ۱.۱۸ باقی مانده‌اند چون انتشار تازه‌ای ساخته نشده است.

پیش از انتشار باید روی اندروید ۱۰ و چند نسخهٔ جدیدتر بررسی کنیم:

- دریافت و refresh روی Wi-Fi و دیتای موبایل؛ حفظ کانفیگ قبلی در خطای SSL/HTML/timeout.
- اتصال VLESS/Reality، VMess، Trojan، Shadowsocks، SOCKS/HTTP و WireGuard با نمونه‌های آزمون مجاز.
- اعلان و سرویس foreground، محدودیت باتری، تغییر شبکه و خاموش‌شدن صفحه.
- انتخاب سرور، حجم/انقضا و Kill Switch؛ تازه‌های parser به معنی رفع مشکلات مستقل این بخش‌ها نیست.

## گام بعدی پیشنهادی

۱. parser معتبر و محدودشدهٔ YAML و نگاشت دقیق تنظیمات Clash/Mihomo و Sing-box.

۲. Import Router برای لینک، فایل، QR، share text و اشتراک، با پیش‌نمایش خطاها و هشدار HTTP.

۳. refresh اتمیک همراه حفظ ID/سرور منتخب و اصلاح dedup/Worker.

۴. مجموعهٔ fixture بدون اطلاعات محرمانه از خروجی‌های Marzban، 3x-ui، Hiddify، Marzneshin و V2Board/XBoard.

۵. ساخت Android و تست روی گوشی؛ سپس تصمیم برای هستهٔ دوم و انتشار آزمایشی.

## گیت‌هاب و فضا

تغییرها فقط در شاخهٔ محلی آماده‌اند. patch شامل گزارش و اصلاحات برای انتقال توسط مالک آماده می‌شود؛ مجوز نوشتن GitHub هنوز موجود نیست، بنابراین push و Pull Request ساخته نشده‌اند. توکن یا کلید خصوصی نباید در چت یا سورس عمومی قرار بگیرد.

پیش از کار فضای دیسک کنترل شد: حدود ۱۹٫۷ GiB آزاد بود. سورس سبک نگه داشته شده، فایل‌های انتشار قدیمی دانلود نشدند و داده‌های کامپایل/گواهی کاملاً آزمایشی داخل `.cache/` هستند. برای وضعیت فعلی نیازی به حذف فایل کاربر یا تاریخچه نیست. ابزار کنترل فضا پایش دائمی خارج از اجرای گفتگو ندارد.
