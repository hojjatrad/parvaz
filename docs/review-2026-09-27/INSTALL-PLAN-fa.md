# مرحلهٔ APK درخواستی مالک

درخواست تازه: اصلاح موارد و تحویل فایل نصب برای آزمایش مالک. انتشار نهایی همچنان BLOCKED است و درخواست تست، تأیید امنیتی یا اجازهٔ حذف gateهای stable نیست.

کشف: worktree پس از بازیابی محیط metadata ناقص داشت؛ metadata از شاخهٔ منتشرشده بازیابی شد، بدون checkout روی سورس موجود. تنها اختلاف gradlew مجوز اجرایی بود که به وضعیت ثبت‌شده برگشت؛ کلید امضا تعویض نشد.

برنامه:
1. رفع بدهی WrongConstant با ثابت‌های نام‌دار هم‌مقدار، نه تغییر رفتار؛ حذف فقط suppressionهای همین دسته از baseline برای آزمون واقعی دوباره. رفتار پینگ و معیار TLS دست‌نخورده.
2. پارامتری‌کردن fixture ارتقا با دو APK قبلی ثابت و SHA256 مشخص: stable39 و TEST41؛ ورودی ناشناخته رد شود. مسیر TEST41 به نامزد جدید واقعاً اجرا شود، نه فقط unit test.
3. برای APK آزمایشی، استفاده از مسیر TEST قبلی همراه با سخت‌گیری اضافه: هر شش باینری native باید دقیقاً با TEST تأییدشدهٔ قبلی برابر باشند و هیچ هشدار فعال تازه یا هشدار Java پذیرفته نشود. خطای اسکن/شبکه fatal است. این معیار فقط عدم پسرفت نسبت به TEST قبلی است، نه رفع ۱۲ مورد باز یا معافیت انتشار نهایی.
4. ساخت/تست/امضای جداگانه در CI، آزمایش نصب و ارتقا، سپس prerelease با برچسب قابل‌دیدن آزمایشی و بدون تغییر Latest. تست جدید ۱٫۲۸٫۸/۴۲، نسخهٔ نهایی بعدی باید حداقل ۱٫۲۸٫۹/۴۳ باشد.
5. شواهد واقعی، محدودیت‌ها و لینک APK در GitHub؛ دانلودهای بزرگ محلی انجام نشوند. اگر نصب/ساخت/اسکن fail شد، نتیجه پنهان نشود و APK موفق اعلام نشود.

ریسک‌ها: ۱۲ مختصات native هنوز نیازمند بررسی‌اند؛ equal-byte بودن با نسخهٔ قبلی به معنی امن بودن نیست. آزمایش جدید فقط برای بررسی مالک است، نه توصیه برای ترافیک حساس. آزمون emulator جای آزمون دستگاه واقعی و همهٔ سناریوهای حفظ داده را نمی‌گیرد. rollback تغییرات کوچک با revert؛ از uninstall برنامهٔ مالک یا حذف داده برای ارتقا استفاده نمی‌شود.
