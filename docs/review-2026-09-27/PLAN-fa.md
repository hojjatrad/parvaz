# ممیزی و برنامهٔ بهبود پرواز — ۲۷ سپتامبر۲۰۲۶

## قرارداد کار و محدوده
اسکیل‌های تازهٔ مالک در `arena/` نگهداری می‌شوند. درخواست تازه اجازهٔ بررسی، تعمیر و بهبود UI را می‌دهد؛ به معنی اجازهٔ حذف داده یا حذف نگهبان انتشار نیست. معیار نهایی همچنان BLOCKED در صورت نقص بحرانی یا نبود شواهد کافی است. تأیید قبلی مالک دربارهٔ پینگ حفظ می‌شود؛ آن را تأیید کل برنامه نمی‌دانیم.

## کشف وضع موجود — VERIFIED با خواندن کد، پیش از تغییر محصول
مبنای واقعی دریافت‌شده از GitHub: `1229029b56b4b08bc521d11aad5e6dedf9543b1e`، نامزد۱٫۲۸٫۸/۴۲. Java17، Android SDK34، minSdk24 (نیاز اصلی مالک Android10+)، رابط XML/AppCompat/Material3، WorkManager، OkHttp، Xray JNI و هسته‌های جداگانهٔ sing-box/Mihomo. ذخیرهٔ پروفایل و تنظیمات مبتنی بر SharedPreferences و لایهٔ رمزگذاری/ژورنال بازیابی است، نه MySQL یا سرویس وب. فارسی/انگلیسی و فونت Vazirmatn موجودند.

### نقشهٔ مسئولیت‌ها
- ورودی و رابط: MainActivity، SettingsActivity، LockedActivity، ui و منابع XML.
- داده و بازیابی: ProfileStore، ProfileIdentity، StoreCipher، RestoreJournal، BackupManager.
- اتصال: TunnelVpnService، CoreManager، ExternalCore، config و مالکیت نسل اتصال.
- پینگ: PingManager → ProxyMeasurement → VerifiedProbe/HttpsLatency → بلیت اندازه‌گیری ProfileStore.
- دریافت و بروزرسانی: SubscriptionRefresh/Worker و UpdateChecker/ResumableDownload/UpdateInstallActivity.
- تحویل: ساخت بدون اسرار → امضای جداگانه → آزمون APK واقعی → بررسی تطابق دقیق بایت‌ها → انتشار.

MainActivity حدود۲۴۷۶ و SettingsActivity حدود۱۱۵۵ خط دارند؛ Adapter مستقیماً به MainActivity وابسته است. بازنویسی یک‌باره ریسک پسرفت دارد؛ جداسازی تدریجی فقط همراه تست مجاز است.

## برنامهٔ تعمیر قابل بازگشت
۱. ثبت قرارداد، این ممیزی، نیازها و معماری؛ بدون تغییر رفتار.
۲. LAB-01: ابتدا آزمونِ شکست ایمن، سپس گارد هدف و اجازه، تست‌های منفی/مثبت؛ rollback یک commit؛ هیچ دستگاه واقعی لمس نمی‌شود.
۳. UI-01..05: نگه‌داشتن IDها و callbackها، منابع تم/فاصله/تاچ مشترک و چیدمان ردیف؛ بدون تغییر موتور/ذخیره/اعتبارسنجی. تست اندازه‌گیری، زبان، تم، فونت، وضعیت و کنتراست. در صورت پسرفت، برگشت همان commit UI.
۴. تست‌های مرتبط و رگرسیون کامل در CI، بررسی diff و هزینهٔ رندر. اندازه‌گیری دستگاه واقعی و تصاویر نصب بدون اجرا VERIFIED نام نمی‌گیرند.
۵. ادامهٔ وابستگی‌ها، انتقال از نسخهٔ پایدار و آزمایشی، حفظ پشتیبان/قفل/منبع و بروزرسانی واقعی؛ سپس ممیزی مستقل انتشار.

## MUST / SHOULD / COULD
MUST: عدم نشت اسرار/حذف داده، حفظ اصلاح پینگ، TLS واقعی و مسیر انتخابی، جلوگیری از نتیجهٔ کهنه، حفظ امضا، فارسی/RTL، کنترل قابل لمس/قابل خواندن، انتشار فقط با شواهد کافی.
SHOULD: زبان بصری یکپارچه، وضعیت خطای قابل اقدام، تفکیک ماژول‌های رابط، صفحهٔ اصلی مناسب گوشی کوچک و تبلت، کاهش کار تکراریِ اثبات‌شده.
COULD: امکانات تازه مانند راهنمای وضعیت‌ها، دسترسی سریع و فیلترهای بهتر پس از تثبیت مسیرهای اصلی؛ نه اضافه‌کردن وابستگی یا ابزار تحلیل‌گر خودکار بدون نیاز.
خارج از این مرحله: بازنویسی کامل، نسخهٔ وب/دسکتاپ مستقل، تضمین اتصال همهٔ سرورهای جهان، اعلام نبودن مطلق باگ.

## مدیریت فضا
بودجهٔ داخلی workspace: هدف زیر۱۲۰MiB؛ پیش از دانلود/ساخت بزرگ، اندازه و فضای آزاد بررسی می‌شود. APK و آرشیو منبع بزرگ فقط در GitHub/CI؛ این مرحله نیازی به دانلودشان ندارد. در صورت عبور از بودجه، کار سنگین متوقف و فقط cache/output شناخته‌شدهٔ قابل بازتولید پاک می‌شود. SOURCE، USER-DATA، CONFIG، TEST، BACKUP، اسناد و UNKNOWN خودکار حذف نمی‌شوند. نتیجهٔ پاک‌سازی در گزارش ثبت می‌شود؛ کلیدهای خصوصی هرگز وارد GitHub نمی‌شوند.
