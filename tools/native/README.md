# Native engines and licensing

Owner authorization for GPLv3 publication was provided in the 2026-09-09 session. Parvaz-owned code is GPL-3.0-or-later; third-party components retain their own licenses. Parvaz is independent and does not imply endorsement by upstream projects.

`engines-lock.json` pins complete source commits and archive SHA-256 values. `build.py` builds Android PIE executables using NDK 27.2.12479018, with linker alignment for 16 KiB pages. Changes to upstream are explicit: the parent-death guard in `parvaz_parent_android.go` and the locked patch under `patches/` for sing-box's optional interface monitor. Android 14 testing exposed a nil-monitor panic in the direct outbound; the patch handles an unavailable monitor in this SOCKS-only child without requesting privileged access. Android, not the child, owns the TUN. The parent guard requests child termination when the application process dies; force-kill/roaming on physical phones remains a separate validation item.

Install Go (at least the versions required by upstream go.mod) and the specified Android NDK, then run `python3 tools/native/build.py`. The resulting native executables are packaged under Android's native library directory, not executed from writable downloaded files. `--probe` builds x86_64 for emulator tests; `--host` builds Linux executables for synthetic loopback protocol tests.

No Android release signing material is involved in native builds. Source bundles for redistribution must include upstream engine trees plus vendored modules and the build instructions; release CI creates these alongside APKs.

The bundle also includes AndroidLibXrayLite (LGPLv3) and its vendored Xray dependencies. `xray-source-lock.json` must match `tools/release/core-lock.json`; automated Xray upgrades update both pins. Rebuild that library following its included upstream build workflow/README, place the compatible AAR at `app/libs/libv2ray.aar`, then build the app without re-fetching the original AAR. Users can modify these build-time pins and sign a modified app with their own key. Export an encrypted backup before replacing an installation signed by a different key; Android will not accept a different signer as an in-place update. The owner's private release key is neither needed nor included.

Full profiles intentionally cannot reproduce desktop listener/process semantics on Android. App-owned loopback/TUN interfaces replace imported listeners; external administration and executable hooks are disabled. File-based inputs cannot escape the private runtime directory. Direct routing rules explicitly present in an advanced file remain direct rules; importing a full profile is not an assertion that it is leak-free. Ordinary subscription import remains server extraction and does not automatically execute imported routing policies.

Before distributing an APK, run `python3 tools/native/source_bundle.py` after the native build and before Gradle. This vendors the matching LGPL wrapper, collects third-party license/NOTICE texts into APK assets and writes the corresponding-source archive. The source archive is a required companion release asset, not a substitute for shipping native dependency notices in the APK. Release validation rejects APKs larger than the existing updater's 128 MiB limit and verifies native ELF load-segment alignment.

Child engines receive a private PEM bundle of public CA certificates obtained from Android's default `X509TrustManager`, rather than assuming legacy Go filesystem CA paths cover Conscrypt's Android 14+ APEX store. The bundle is deleted with the session. No private keys are exported; hostname/certificate verification remains enabled unless the imported profile explicitly opts out. Emulator QUIC fixtures use a disposable self-signed server with an explicit test-only opt-out; separate host fixtures test strict trust and wrong-SNI rejection.

Lifecycle follow-up: Android API 29 reproduced that Linux `PR_SET_PDEATHSIG` also fires when the *forking thread* exits while its process survives. `ExternalCore` therefore forks on a private long-lived executor thread, not on a transient caller; synchronized launch/close prevents a queued launch after cancellation cleanup. The guard is retained. Probe tests distinguish caller-thread completion from owner-process death (observed by Binder death and listener closure/rebind). These are not full-app TUN/kill-switch proofs. The follow-up helper's debug-only network-security configuration trusts its disposable test CA; QUIC tests now keep certificate verification enabled and reject wrong SNI. No test CA/configuration is added to the production app.
